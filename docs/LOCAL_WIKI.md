# 本地资源 Wiki

本地网站用于结构化浏览已经下载的图片和视频，视觉参考绝区零 Wiki 的档案区域：黑灰底色、黄色选中标签、分类导航、主题分组、图片放大和视频播放。它不是完整 Wiki 镜像，不含角色图鉴、攻略、账号或评论。

## 数据与离线访问

- 优先读取下载器每次运行保存在本地 `state/wiki.json` 的最新清单快照；尚无快照时读取项目中的 `metafiles/wiki.json`。沿用同一个 Wiki 清单格式，不增加 Git 跟踪的元数据文件。
- 图片和视频来自本地下载目录，页面、样式与背景也在本地。运行期间不会请求官网、CDN、在线字体或统计服务。
- 显示四类资源：角色视频、游戏视频、壁纸收录、好感壁纸。可以搜索主题、分组和文件名。
- 每个分组通过标签切换文件；图片可放大、用左右方向键浏览，视频支持拖动进度条，媒体可保存原文件。
- 同主题的不同尺寸壁纸合并展示，例如「洛克茜主题壁纸」下用 16:9 / 21:9 切换构图，悬停显示实际尺寸。同一比例有多种尺寸时额外显示分辨率；2560×1080 按常用名称显示为 21:9。默认选像素较多的版本，切换比例尽量保留当前图片序号。仅合并网页分组，不改变清单、下载目录或已下载文件。
- 主题列表按原图比例瀑布流排列，封面不裁切，并继续随滚动分批加载。来源接口提供的图片宽高会保留在清单中；没有尺寸时，由下载任务为每个主题的一张预览图读取元数据并增量保存到本地 `state/image-sizes.json`。文件未变化就不再读取图片；网站重启后也可复用缓存。没有本地索引的旧部署首次访问时会读取预览图尺寸并在内存缓存。
- 详情图片按内容宽度展示，竖图可沿页面向下阅读。放大窗口对竖图默认适宽阅读，并可切换“整图适屏”；横图默认整图适屏。
- 标签优先显示 Wiki 原有的版本、活动或主题名称；纯序号标签显示为 1、2 等。只有一个资源的分组不显示多余的切换标签。清单仅保留有意义的 `caption` 名称，增量更新会继续保留它们；下载文件名和目录不变。
- 尚未下载的文件显示占位。下载器的 `.zzz-partials` 不会展示；下载完成后刷新页面即可识别。
- 网站只读挂载资源，不修改下载记录和文件。JSON 更新后刷新网页即可，无需重启服务。
- 图片封面直接使用本地图片。视频主题的 `cover_url` 来自 Wiki 目录接口的 `icon`；下载器在处理媒体前增量缓存到 `state/covers`，网页用于列表封面和播放器预览，运行时不会请求远程封面。封面缓存与记录不进入“官方资源”目录，也不会改变已有媒体的路径或下载记录。
- 旧清单没有 `cover_url`、封面尚未下载或缓存缺失时，页面继续使用占位封面。正常运行一次下载器后刷新页面即可看到封面，无需重新下载视频。已有封面按本地下载记录跳过；手动删除缓存后可使用下载器的 `--verify-files` 检查并补齐。
- 好感壁纸和动态壁纸的视频在下载任务结束后，由 FFmpeg 从本地文件的第一帧生成静态缩略图，保存在 `state/thumbnails/`。首次对已完成的视频补生成，以后按内容指纹和已下载文件的 SHA-256 复用记录；不因启动、目录改名或链接签名续期重新扫描视频。网页只读取缓存图片，不执行 FFmpeg。缩略图生成失败会保留视频并在下次任务重试。
- 动态壁纸合集主页优先使用上传日期最新、且已有缩略图的视频作为预览，同日或没有日期时沿用 Wiki 顺序。新增壁纸下载并生成缩略图后，刷新网页就能更新预览；每段视频播放器使用自己的缩略图。官方封面或现有静态图片优先于生成的备用缩略图。

## Synology Container Manager

先在现有 Git 项目中更新代码，然后使用独立的 Compose 文件启动网站。它与每天运行一次的下载器是独立的项目。

```sh
git pull --ff-only origin main
sudo docker compose --env-file .env -f compose.wiki.yaml up -d --build
```

在项目根目录执行以上命令。现有 `.env` 中的 `NAS_UID`、`NAS_GID`、`STATE_PATH` 和 `DOWNLOAD_PATH` 会复用，**下载目录不需要移动**；网站只读挂载 `state`，HTTP 服务只公开清单目录和清单内的媒体，不公开数据库、日志或 `.env`。

更新后下次每日下载任务会自动保存最新清单快照。首次启动没有快照也可浏览仓库已有清单；快照生成后刷新页面自动切换，不需要每天为了网页更新而 `git pull`。

可在 NAS 本地 `.env` 中另外设置端口，例如：

```dotenv
WIKI_PORT=8080
```

浏览器打开 `http://NAS的局域网IP:8080`。同一局域网的电脑、平板和手机均可访问；NAS 断网仍可浏览本地资源，但 NAS 本身必须开机。`localhost` 仅表示浏览器所在的设备，因此手机上要使用 NAS IP。

这里没有账号登录，适用于可信局域网。无需设置公网端口转发。如果 DSM 防火墙启用，需要允许局域网访问所选端口。

网站设置为 `restart: unless-stopped`，NAS 开机且 Docker 服务启动后会恢复运行，不需要另加 Wiki 启动脚本或开机任务。
下载器仍由原来的每日任务启动，每次任务会先更新代码；若代码发生变化，会重启正在运行的 Wiki。每日任务命令不需要改。

查看服务日志：

```sh
sudo docker compose --env-file .env -f compose.wiki.yaml logs --tail=50 -f wiki
```

停止网站：

```sh
sudo docker compose --env-file .env -f compose.wiki.yaml stop wiki
```

通常每日下载任务会自动更新。需要立即更新时，可以手动运行原来的每日任务，或执行：

```sh
git pull --ff-only origin main
sudo docker compose --env-file .env -f compose.wiki.yaml up -d --no-build --force-recreate
```

源代码、前端和 metafiles 都从 Git 项目只读挂载。每日下载脚本会同步 main，必要时重启网站；普通代码更新不构建镜像，依赖变化时才自动构建。

## 调试模式

默认隐藏侧栏主题数量、主题卡片的资源/已下载数量，以及分组资源数量。图片切换序号和未下载提示保留，方便正常浏览。

需要核对数据时，在 NAS 本地 `.env` 中设置 `WIKI_DEBUG=true`，然后执行：

```sh
sudo docker compose --env-file .env -f compose.wiki.yaml up -d --no-build --force-recreate wiki
```

改回 `WIKI_DEBUG=false` 并执行同一命令即可恢复正常模式。本机启动可使用 `python -m src.wiki --debug`。此选项只控制页面核对信息，不开启开发调试服务器。

## Windows 本机预览

在项目根目录执行：

```powershell
python -m src.wiki --downloads 'D:\你的本地资源目录'
```

打开 `http://localhost:8080`。未指定目录时使用项目的 `downloads`。如果希望同一局域网设备访问该电脑，可以加 `--host 0.0.0.0`，并按需允许 Windows 防火墙的专用网络访问。
